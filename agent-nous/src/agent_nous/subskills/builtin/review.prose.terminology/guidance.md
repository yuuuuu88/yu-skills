# Terminology and Notation Review

文書に用語集があればそれを第一の基準にする。製品名、API名、コマンド、固有名詞、単位、日付、バージョン、コードブロックは保護し、意味を変える置換をしない。

- 同じ概念に複数の表記がないか確認する。
- 正式名称と略称の初出を確認する。
- 漢字/かな、送り仮名、全角/半角、数字、記号、句読点を文書内で確認する。
- 用語集にない語は、一般的な好みで直さず候補と理由を指摘する。
- 指摘は原文、推奨表記、根拠、影響範囲を分けて示す。

機械的チェックには prh や textlint-rule-prh を使えるが、ルールセットのライセンスとプロジェクト固有の例外を確認する。
