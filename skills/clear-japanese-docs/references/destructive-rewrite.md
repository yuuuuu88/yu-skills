# 既存文書の破壊的な再構成

## 基本姿勢

「分かりやすくする」と依頼された場合、元の文章を残したまま言い換えることだけを正解にしない。読者の目的に合わせて、文書の構造を作り直す。

## 変更の分類

| 分類 | 判断 |
|---|---|
| 残す | 正確で、主読者の目的に必要 |
| 移動する | 内容は必要だが、現在の場所では理解を妨げる |
| 統合する | 同じ内容や似た説明が複数ある |
| 削除する | 重複、古い情報、目的外の脱線、根拠のない断定 |
| 追加する | 不足している前提、例、成功条件 |

## 安全な編集手順

1. 元文書と関連文書を読み、参照関係を確認する。
2. 主読者、目的、適用範囲を明文化する。
3. 各節を「残す・移動・統合・削除・追加」に分類する。
4. 結論、前提、概要、最短経路の順に再配置する。
5. 重複や不要な節を削除し、必要なら複数文書を統合する。
6. 事実、推測、未確認事項を分ける。
7. 重要な情報が失われていないか確認する。
8. 完成文書の後に構成変更の要約を出す。

## 削除してはいけないもの

短くしても意味を保ったまま残す。

- セキュリティ、法務、契約、コンプライアンス上の注意
- 失敗時の復旧方法
- 適用条件、制約、例外
- データの出典や検証方法
- 読者が誤操作しないための警告

矛盾する情報は勝手に一方を採用せず、確認事項として示す。

## 編集結果の報告

- 章や節の主な移動
- 削除・統合・追加した内容
- 元文書のどの問題を解消したか
- 未確認の事実や人による確認が必要な点
