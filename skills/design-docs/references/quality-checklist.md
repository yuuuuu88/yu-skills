# 品質チェックリスト

## 入口と構造

- [ ] `docs/README.md` から全領域へ辿れる。
- [ ] 各ディレクトリのREADMEが責務、正本、命名規則を説明している。
- [ ] 各文書のIDが一意である。
- [ ] `source_of_truth` と参照先が明確である。
- [ ] 相対リンクが壊れていない。
- [ ] 旧パスや重複正本が意図せず残っていない。

## 要件と追跡性

- [ ] 目的・ユーザーニーズ・ステークホルダー要求・機能要件・品質要件・制約にIDがある。
- [ ] 各要件に設計書または `not-applicable` の理由がある。
- [ ] 各設計要素が少なくとも一つの要件または明示した技術制約に接続している。
- [ ] 要件から設計、図候補/ADR、テスト、リリース、運用、廃止まで辿れる。
- [ ] 受入条件に検証方法があり、品質要件が測定可能である。
- [ ] 図だけに存在する仕様がなく、本文または契約の正本へ接続している。

## 適用判定と差分

- [ ] 文書カタログの全項目が `required` / `conditional` / `not-applicable` のいずれかであり、`required`の例外判断も同じ形式で残っている。
- [ ] `conditional` に適用条件と再評価トリガーがある。
- [ ] `not-applicable` に理由、代替/統合先、再評価トリガー、判断者、判断日がある。
- [ ] 枝はベース文書IDとベース版を指定している。
- [ ] 枝のfront matterに `base_document` と `base_version` がある。
- [ ] 枝に共通文書のコピーがなく、追加・変更・制限・削除の差分だけがある。
- [ ] 要件、API、データ、UI、セキュリティ、運用、図、テストの差分を確認している。
- [ ] ベース更新時の再適用と、差分間の衝突ルールがある。

## 文体・内容

- [ ] 主読者、目的、対象範囲、非対象範囲、前提、制約が冒頭で分かる。
- [ ] 一文一義で、主語・動作・対象・条件が明確である。
- [ ] 「適切に」「高速に」など、検証不能な表現が残っていない。
- [ ] 事実、推測、仮定、未決事項が区別されている。
- [ ] `status` は文書ライフサイクルであり、作業進捗が混入していない。
- [ ] front matter、文書版、対象プロダクト版、更新日、関連IDがある。
- [ ] 共通front matterは `related_requirements`、`related_designs`、`related_diagrams`、`related_adrs`、`related_tests` を使い、差分文書は `base_document` と `base_version` を使う。
- [ ] 重要な判断に理由とトレードオフがあり、必要ならADRがある。

## 図

- [ ] 各図候補に問い、目的、読者、対象範囲、最小要素、更新トリガーがある。
- [ ] 図種が内容に合い、過剰な図を強制していない。
- [ ] 後付け図は図ID付きプレースホルダーから開始している。
- [ ] 図仕様に関連要件・ADR、凡例、関係ラベル、alt text、ソース/生成物の場所がある。
- [ ] 図の状態が `planned → draft → in-review → approved → deprecated` で管理されている。
- [ ] 後付け順序が `placeholder → spec → editable source → rendered → review` である。
- [ ] 図本体を今回作らない場合、その非ゴールが明記されている。

## 安全性・根拠

- [ ] API key、private key、パスワード、個人情報、本番データを含まない。
- [ ] 外部資料にはURL、資料名、調査日、適用範囲がある。
- [ ] 標準の要求と、Skillが採用する実務上の推奨を区別している。
- [ ] セキュリティ、プライバシー、保持・削除、復旧を適用判定した。

## 自動検査の最低限

- [ ] 必須ファイル（Skill、agent設定、7つ以上のreference）が存在する。
- [ ] Markdownの相対リンクを実在パスへ解決できる。
- [ ] IDの重複、front matterの必須キー不足、欠落した関連IDを検出した。
- [ ] リポジトリのsecret scannerまたは同等の検査で、秘密情報がないことを確認した。
- [ ] 許可範囲外のファイル、コミット、push、外部送信がないことを確認した。
- [ ] 外部URLは名称、用途、調査日を持ち、取得不能な場合は未確認として記録した。

## 再現可能な実行

リポジトリルートで次の読み取り専用検査を実行する。

```bash
python3 skills/design-docs/scripts/validate_design_docs.py .
```

この検査は、必須ファイル、Skill front matter、agent設定、相対リンク、READMEのSkillリンクと非リンク差分、関連メタデータ、秘密情報らしき値、図の実体、`nous-pilot/` のtracked diffを確認する。外部URLの到達性は、同じ検証記録へ取得日と結果を追記する別の読み取り専用手順で確認する。

## 完了条件

このチェックリストを通過し、未解決事項が残る場合は、未解決事項のID、影響、判断者、次の確認方法を出力する。「ファイルがある」だけで完了とはしない。
