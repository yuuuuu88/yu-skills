# アイコンポリシー

## 既定はアイコン中心

`assets/icons/manifest.json`に、一般概念と公式プロバイダー製品を登録する。ノードはアイコンを主役として大きく置き、ラベルと役割は別の編集可能なテキストとして近くに置く。ノードを「四角＋文字」だけで表現したり、アイコンを小さな飾りへ縮めたりしない。

- `generic.*` はLucide 1.30.0のISC SVGをベースにし、利用者、ブラウザ、API、コンテナ、サーバー、DB、キュー、ネットワークなどの概念へ使う。
- アイコンは画像オブジェクト、ラベル、役割、コネクタを別々のPowerPointオブジェクトにする。
- 公式アイコンは `provider` と実在する製品名を指定した時だけ選ぶ。
- アイコンと製品名/役割のテキストを別オブジェクトにする。
- アイコンだけで意味を伝えない。製品名または短い概念ラベルを近くに置く。
- PowerPointの図形はゾーン、境界、凡例に使い、サービスノードの代わりに空の角丸箱や丸枠を描かない。
- 同梱アイコンを特定ベンダー製品の公式アイコンに見せかけない。

## ベンダー固有アイコン

AWS、Azure、Microsoft 365などの製品を表す場合は、ユーザー提供の許諾済み素材、または公式配布元から都度取得した最新版を使う。取得日、配布元URL、利用条件、アイコン名を納品メモに残す。出典が確認できない第三者アイコン集を、公式素材として扱わない。

公式ガイドの共通方針:

- 製品名をアイコンの近くに書く。
- アイコンを切り抜き、反転、回転、変形、勝手な色変更をしない。
- ベンダーアイコンを自社サービスや一般概念の代用にしない。
- アイコンの利用許諾が対象用途（社内資料、顧客資料、公開資料など）に合うか確認する。

未収集のアイコンは `manifest.json` の解決規則に従って、意味の近いgenericアイコンへフォールバックする。生成時に `*.pptx.icons.json` と標準エラーへ解決結果を出し、無表示にしない。特定製品の正確な表現が必要な場合は、公式資産を追加収集してmanifestへ登録する。

参照:

- [Azure architecture icons](https://learn.microsoft.com/en-us/azure/architecture/icons/)
- [AWS architecture icons](https://aws.amazon.com/architecture/icons/)

## 更新と不確実性

アイコンセットは更新される。スキル内の中立アイコンは固定資産として扱えるが、ベンダーアイコンは毎回公式配布元を確認する。ユーザーが「AWSのアイコンで」と指定しても、利用条件が不明なら、まず中立図形で作り、差し替え対象を明示する。
