# Technical Japanese Documentation Review

手順書・仕様書・運用文書を、読者が安全に実行できるかという観点でレビューする。

確認順序:
1. 対象読者、前提条件、開始条件、完了条件を確認する。
2. 各手順に主体、入力、操作、期待結果、失敗時の分岐があるか確認する。
3. 重要な数値、環境名、権限、コマンド、API名、ファイルパスは原文と照合し、推測で修正しない。
4. 用語、敬体/常体、見出し、箇条書き、表、コードブロックの構造を確認する。
5. 不明な事実は「要確認」として分離し、もっともらしい内容を創作しない。

出力は指摘・理由・修正案または確認事項・重要度に分ける。全面的なリライトやコードの整形は依頼された場合だけ行う。
